# Формы откликов — конструктор форм для карьерной платформы студентов

Менеджер сам собирает форму отклика на стажировку или мероприятие, публикует её по уникальной ссылке
и смотрит ответы и конверсию. Студент открывает ссылку (с компьютера или телефона) и отправляет ответы.
Разработчики для новой формы больше не нужны.

## Быстрый старт

Нужны **Node.js 20.9+** и npm (проверено с чистой установки на Node 20.9, 20.20, 22 и 24). Из корня репозитория:

```bash
npm install
```

```bash
npm start
```

`npm start` собирает production-сборку (`next build`, ~15–30 с) и запускает сервер.
После строки `✓ Ready` сервис доступен на **http://localhost:3000**:

| Что | Адрес |
|---|---|
| Админка (без авторизации) | http://localhost:3000/admin |
| Публичная форма | `http://localhost:3000/f/<publicId>` — ссылку выдаёт админка после публикации |

Другой порт задаётся переменной `PORT`:

```bash
PORT=4000 npm start
```

(Windows PowerShell: `$env:PORT=4000; npm start`, cmd.exe: `set PORT=4000 && npm start`.)
Если порт занят, `next start` завершится с ошибкой `EADDRINUSE` — укажите другой порт так же.
Повторный запуск без пересборки — `npm run serve`.

Никаких API-ключей, облачных сервисов и отдельной СУБД: данные хранятся в `data/db.json` внутри проекта,
шрифт и иконки поставляются npm-пакетами, сборка работает без интернета.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `DATA_DIR` | `./data` | папка с файлом данных; если она недоступна для записи, сервер не стартует и пишет понятную причину |
| `ALLOWED_HOSTS` | — | доменные имена для админки через запятую, без порта. Без настройки админка открывается по `localhost`, IP-адресу (например, с телефона в той же сети) и имени компьютера без точки (`http://devbox:3000`) |

## Ключевые решения

- **JSON-файл вместо SQLite.** SQLite на Node 20 требует нативного драйвера, а npm 11 по умолчанию не запускает
  install-скрипты пакетов — у проверяющего драйвер мог бы не собраться. Запись в файл атомарная и строго
  по очереди (подробнее — в «Модели данных»).
- **Ответ хранит снимок вопросов.** Форму можно править и после публикации: старые ответы показываются так,
  как их видел студент, а CSV разводит ответы до и после смены типа вопроса по разным колонкам.
- **Никаких «тихих» потерь.** Устаревшее сохранение из второй вкладки получает `409`, а не затирает чужие правки;
  студент, у которого форма изменилась во время заполнения, получает новую версию с сохранёнными ответами;
  повторная отправка не создаёт дубликат; текст, который браузер не смог разобрать в поле числа или даты,
  блокирует отправку, а не уходит пустым ответом.
- **Аналитика отвечает на вторую проблему из ТЗ** — где студенты бросают форму: воронка «открыли → начали →
  отправили» и последний вопрос в брошенных сеансах, только по реальным событиям.
- **Открытая админка (по ТЗ) защищена от чужих сайтов:** проверка `Origin`/`Sec-Fetch-Site` и типа тела запроса,
  белый список имён хоста против DNS rebinding, CSP и запрет встраивания.

## Как создать и опубликовать форму

1. Откройте `/admin` → **«Создать форму»**.
2. Во вкладке **«Конструктор»** задайте название и описание, добавьте вопросы из панели «Добавить поле»
   (или кнопкой «Добавить базовые поля»). Для каждого вопроса: текст, подсказка, плейсхолдер, обязательность,
   тип; для списков — варианты ответа. Порядок меняется стрелками ↑/↓, вопрос можно дублировать и удалить.
3. **«Сохранить»** (или Ctrl/Cmd+S). Вкладка **«Предпросмотр»** показывает форму глазами студента,
   включая несохранённые правки (переключатель «Компьютер / Телефон»).
4. **«Опубликовать»** → появится публичная ссылка с кнопками «Копировать» и «Открыть». Если в форме остались
   тексты-заготовки («Новый вопрос», «Вариант 1»), админка перечислит их и попросит подтвердить публикацию.
5. Студенты заполняют форму по ссылке. Ответы — во вкладке **«Ответы»** (таблица, карточка ответа,
   экспорт CSV), воронка заполнения — во вкладке **«Аналитика»**.
6. **«Снять с публикации»** закрывает приём ответов: ссылка показывает «Форма сейчас не принимает ответы».

## Возможности

- **10 типов полей:** короткий и длинный текст, email, телефон, число (с мин./макс.), выпадающий список,
  один из списка, множественный выбор, дата, флажок-согласие.
- **Серверная валидация** по актуальной схеме формы: обязательность, форматы, тип и диапазон числа, допустимые
  варианты, управляющие символы. Клиент использует тот же модуль (`lib/schema.ts`) для мгновенных подсказок,
  но сервер ему не доверяет.
- **Неопубликованные формы** не отдают содержимое и не принимают ответы (403).
- **Экспорт CSV** для Excel: UTF-8 с BOM, разделитель `;`, десятичная запятая, время в часовом поясе менеджера
  (указан в заголовке колонки), защита от формул.
- **Черновик ответов студента** хранится в `sessionStorage` вкладки и переживает перезагрузку страницы.
- **Доступность:** подписи и `fieldset/legend`, `aria-invalid`/`aria-describedby`, сводка ошибок с переходом
  к полю, управление с клавиатуры (вкладки, диалоги, перестановка вопросов без перетаскивания), фокус-кольцо
  с контрастом ≥ 3:1. Проверка axe-core (WCAG 2.2 AA) на всех экранах — без нарушений.
- Адаптивный интерфейс до ширины 320 px; дизайн Organic, шрифт Rubik с кириллицей, иконки Lucide.

### Методика аналитики

Цифры считаются только по реальным событиям, ничего не достраивается:

- **Просмотр** — форма отрисовалась у студента (один раз за сеанс вкладки; сеанс хранится в `sessionStorage`,
  поэтому перезагрузка не удваивает просмотры).
- **Начало заполнения** — студент впервые **изменил значение** любого поля (не фокус и не загрузка страницы).
- **Отправка** — успешно сохранённый ответ.
- **Конверсия** = отправившие из начавших. По каждому вопросу — сколько сеансов его заполнили и на скольких
  брошенных сеансах он был последним, к которому студент приступил: так видно, где студенты уходят.
- В предпросмотре события не отправляются. Если данных нет, показывается «—», а не 0%.

## Архитектура

**Next.js 16 (App Router, Cache Components) + React 19 + TypeScript + Tailwind CSS 4.** Один процесс
обслуживает и интерфейс, и JSON API (route handlers).

```
app/
  admin/                    админка: список форм и редактор (/admin/forms/[id]?tab=…)
  f/[publicId]/             публичная форма студента
  api/forms/**              админ-API: CRUD, публикация, ответы, CSV, аналитика
  api/public/forms/**       публичное API: схема формы, отправка ответа, события аналитики
  api/[...slug]/            JSON-404 для неизвестных маршрутов API
components/                 UI: конструктор, вкладки редактора, FormRenderer (общий для предпросмотра и публичной формы)
lib/schema.ts               общая схема: типы полей, нормализация формы, валидация ответов (клиент + сервер)
lib/answers.ts              логика ответов студента в браузере: черновик, перестройка при смене формы
lib/api-client.ts           типизированный клиент API (типы ответов берутся из серверного кода)
lib/server/store.ts         файловое хранилище data/db.json
lib/server/forms.ts         бизнес-логика: формы, ответы, CSV, аналитика
lib/server/http.ts          формат ошибок, разбор тела запроса, проверка источника, rate limit
lib/server/host.ts          белый список имён хоста (защита админки от DNS rebinding)
proxy.ts                    применяет белый список хостов к /admin и /api/forms (Next 16 Proxy)
instrumentation.ts          проверка папки данных при запуске сервера
next.config.ts              заголовки безопасности (CSP и др.), Cache Components
docs/API.md                 полный API-контракт
test/, e2e/                 unit- и HTTP-тесты (vitest), браузерные тесты (Playwright)
AGENTS.md                   подсказка Next.js 16 для AI-агентов (её поддерживает `next dev`)
```

### Модель данных и хранение

`data/db.json` содержит три коллекции:

- `forms` — `id` (для админки), `publicId` (10 случайных символов для ссылки, без похожих `I/l/1`, `O/0`),
  `title`, `description`, `fields[]`, `status` (`draft`/`published`), `version` (растёт при каждом сохранении), даты.
- `responses` — `formId`, `submissionId`, `answers` (по id полей), `formVersion` и `fields` — снимок вопросов
  на момент отправки.
- `sessions` — сеансы аналитики: когда открыли, начали, отправили, какие поля трогали.

Надёжность файла:

- изменения выполняются строго по очереди над черновой копией данных и пишутся **атомарно**
  (временный файл → `fsync` → `rename`); только после успешной записи копия становится текущим состоянием,
  поэтому сбой записи не оставляет «фантомных» данных. Событие, которое ничего не меняет, на диск не пишется;
- повреждённый файл не теряется: он переименовывается в `db.corrupt-<время>.json`, сервер стартует с пустой базой,
  пишет предупреждение в лог и показывает его в админке. Файл, сохранённый редактором с BOM, читается нормально;
- при запуске проверяется, что `DATA_DIR` доступна для записи, — иначе понятная ошибка вместо 500 на каждом сохранении.

### Безопасность

- Ввод: лимит тела 200 КБ (потоково), только JSON (`415` для других типов), серверная валидация всех полей,
  неизвестные поля ответа отбрасываются, id вида `__proto__` запрещены.
- Открытая админка: изменяющие запросы с чужих сайтов отклоняются (`Origin`, `Sec-Fetch-Site`), имя хоста
  проверяется против DNS rebinding.
- Заголовки: CSP (`default-src 'self'`; inline-скрипты разрешены — nonce несовместимы с частичным пререндерингом,
  `unsafe-eval` только в режиме разработки), `X-Frame-Options: DENY`,
  `Permissions-Policy`, `nosniff`, `Referrer-Policy`, без `X-Powered-By`.
- Публичные маршруты: rate limit на клиента и на форму целиком (`429` с `Retry-After`), лимиты 10 000 ответов
  и 20 000 сеансов на форму.
- Вывод: пользовательский текст выводится только как текст; в CSV нейтрализуются формулы.

## Известные ограничения

- Админка без авторизации — по условию задания. Любой, кто знает адрес `/admin`, может управлять формами.
- Хранилище рассчитано на один процесс и умеренные объёмы: весь файл держится в памяти и переписывается
  при каждом изменении. При сотнях ответов запись занимает миллисекунды; на пределе одной формы
  (10 000 ответов, 20 000 сеансов, файл 39 МБ) — около 0,3 с, и на это время сервер занят. Следующий шаг — встроенный
  в Node `node:sqlite` (без нативных зависимостей), когда поддержка Node 20 станет не нужна.
- В CSV значения, начинающиеся с `=`, `+`, `-`, `@`, табуляции или `\r` (кроме полей «Число»), получают
  префикс `'` (защита от формул), поэтому телефоны вида `+7 …` выгружаются как `'+7 …`.
- Если у вопроса сменили тип, в аналитике по полям он по-прежнему считается одним вопросом.
- Аналитика best-effort: идентификатор сеанса создаёт браузер, поэтому накрутку можно ограничить, но не исключить;
  «начали, но не отправили» включает и тех, кто заполняет форму прямо сейчас.
- Общий лимит на форму (600 отправок в минуту) можно исчерпать, подделывая `X-Forwarded-For`, — тогда форма
  на минуту перестанет принимать ответы.
- `npm install` пишет две вещи про инструменты разработки, на приложение они не влияют:
  - «eslint@9 … no longer supported» — ESLint 10 пока не поддерживают плагины из официального `eslint-config-next`
    (их peer-зависимости — до ESLint 9); с ESLint 10 npm выдаёт конфликт зависимостей, поэтому выбран ESLint 9;
  - «5 high severity vulnerabilities» — пакет `braces` в том же `eslint-config-next`, исправленной версии нет;
    в зависимостях приложения уязвимостей нет (`npm audit --omit=dev`).
