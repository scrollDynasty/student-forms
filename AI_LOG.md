# Лог работы с AI

Инструмент: **Claude Code** (модель Claude Opus 5.5) в десктоп-приложении Claude, с установленным плагином
**Everything Claude Code (ECC) 2.2.3**. Ниже — фактическая хронология сессии от 21.10.2026: что делалось,
какие решения принимались и чем они проверялись. Полная переписка сессии хранится в Claude Code и может быть
предоставлена по запросу.

## 1. Исследование и требования

- Прочитан `TZ.txt`. Репозиторий содержал только ТЗ: кода, git и прежнего AI-лога не было.
- Выделены легко упускаемые требования: запуск строго `npm install` + `npm start`, порт из `PORT`,
  `/admin` без авторизации, данные внутри проекта, никаких внешних сервисов (в т.ч. сетевых шрифтов при сборке),
  неопубликованные формы не принимают ответы, история ответов не должна ломаться при редактировании формы,
  аналитика конверсии без выдуманных цифр.

## 2. Первый вариант стека и его замена (по указанию пользователя)

- Изначально был выбран Express + React 18 + Vite 6 (ради совместимости с любым Node 20.x), написан API-контракт
  `docs/API.md` и общий модуль валидации по TDD (RED: модуль отсутствует → GREEN: 17 тестов).
- Пользователь остановил работу: нужен TypeScript, самые свежие версии пакетов и стандартная структура проекта
  от официального генератора, а не собранная вручную.
- Сравнены актуальные версии (npm registry): Next.js 16.4.2 (Node ≥ 20.9), Vite 8.3.5 (Node ≥ 20.19),
  React Router 8.5 (Node ≥ 22.22), Express 5.3. Выбран **Next.js 16 + TypeScript**: один фреймворк закрывает UI,
  API (route handlers) и маршрутизацию, `next start` сам читает `PORT`, а требование ТЗ «Node 20+» сохраняется.
- Проект пересоздан через `npx create-next-app@latest --yes` (App Router, TypeScript, Tailwind CSS 4, ESLint,
  Turbopack); все пакеты обновлены до `@latest` (TypeScript 7.0.2, React 19.3.1, ESLint 10, Tailwind 4.3).
- `next/font/google` (скачивает шрифт при сборке) заменён на npm-пакет `geist` — сборка работает без интернета.
- Хранилище: JSON-файл с атомарной записью вместо SQLite — npm 11 блокирует install-скрипты пакетов,
  поэтому нативные драйверы вроде `better-sqlite3` могут не собраться у проверяющего.

## 4. Реализация бэкенда (TDD)

- `lib/schema.ts` — общая для клиента и сервера схема: 10 типов полей, нормализация формы, валидация ответов.
  RED на 3 новых теста (зарезервированные id, строгий email/телефон, генератор UUID) → GREEN 20/20.
- `lib/server/store.ts` — JSON-хранилище: запись через временный файл + fsync + rename, объединение
  параллельных записей, резервная копия повреждённого файла. RED (модуль отсутствует) → GREEN 6/6.
- `lib/server/forms.ts` + `app/api/**` — CRUD, публикация, серверная валидация, идемпотентные отправки,
  снимок схемы в каждом ответе, CSV, аналитика сеансов. 25 контрактных HTTP-тестов запускают настоящий
  `next start` на случайном `PORT` с отдельной папкой данных (включая перезапуск сервера).
- Найдено по ходу: GET-обработчики при включённых Cache Components пререндерились бы при сборке — добавлен
  `await connection()`; `fetch().text()` съедает BOM — тест CSV проверяет сырые байты.

## 5. Интерфейс

- Фронтенд-агент (роль Frontend) реализовал по `docs/API.md`: список форм, редактор с вкладками
  «Конструктор / Предпросмотр / Ответы / Аналитика», публичную форму `/f/[publicId]`. Перед кодом он изучил
  встроенную документацию Next 16 (`node_modules/next/dist/docs`): параметры динамических маршрутов читаются
  внутри `<Suspense>` из-за Cache Components.
- Принятие результата — не по отчёту агента, а по собственной проверке: `npx eslint .`, `npx tsc --noEmit`,
  `npm test` (58/58), затем браузерный E2E.

## 6. Независимые ревью и исправления

| Ревьюер (ECC agent) | CRITICAL / HIGH | Что исправлено |
|---|---|---|
| `ecc:security-reviewer` (бэкенд) | нет | потоковый лимит тела запроса (chunked), rate limit публичных POST, лимит ответов на форму, проверка `Origin` для админ-API, числа-переполнения (`Infinity` → `null` в JSON), формулы в CSV для телефонов, безопасное имя файла CSV |
| `ecc:typescript-reviewer` (бэкенд) | нет | хранилище: очередь изменений над черновой копией — сбой записи больше не оставляет «фантомных» данных в памяти; `PUT` без `fields` больше не стирает поля; стабильная сортировка; `npm test` сначала собирает проект; ESLint снова работает |
| `ecc:react-reviewer` (интерфейс) | нет | защита несохранённых правок при кнопке «Назад» браузера, отмена удаления вопроса и восстановление вариантов при смене типа, фокус на ошибке при сохранении из другой вкладки, постраничный вывод ответов, честный «телефонный» предпросмотр (container queries), контраст, фокус после удаления и публикации, `h1` на экране успеха |

Каждое исправление бэкенда шло через RED → GREEN: сначала тест, воспроизводящий проблему
(например, запись в каталог только для чтения, chunked-тело 4 МБ, 35 отправок подряд, кросс-доменный `DELETE`),
затем код.

Примечательные решения по ходу:
- typescript-eslint не поддерживает TypeScript 7 — применена официальная схема из анонса TS 7
  («Running side by side with TypeScript 6.0»): `"typescript": "npm:@typescript/typescript6"`
  и `"@typescript/native": "npm:typescript@^7.0.2"`; `npx tsc` остаётся версии 7.0.2.
- ECC-хук config-protection запретил ослаблять конфиг ESLint — вместо этого в двух тестовых файлах добавлена
  явная директива с обоснованием (тесты разбирают нетипизированный JSON).
- Во время работы `package.json` был перезаписан извне (вероятно, из открытого редактора) — пропали `geist`
  и `vitest`, а `react` и `react-dom` разошлись по версиям. Зависимости восстановлены, версии выровнены,
  пользователь предупреждён.

## 12. Проверка оставшихся замечаний (по просьбе пользователя: «убеждайся, что проблемы точно есть»)

Каждое замечание сначала воспроизводилось в браузере (Playwright на production-сборке, реальные нажатия клавиш);
неподтверждённые не исправлялись.

- Подтверждено и исправлено:
  - P2: в публичной форме текст, который браузер не может разобрать в поле «Число» («1-2») или недописанная
    дата («12/дд/гггг»), отдаёт значение `""` — необязательный ответ молча отправлялся пустым, студент видел
    «Ответ отправлен». Теперь такая отправка блокируется сообщением «Введите число» / «Введите дату
    полностью» (`validity.badInput` читается из самих полей при отправке и по событиям `input`/`blur`).
  - P3: в конструкторе «1-2» в «Минимум/Максимум» выглядело введённым, но форма считала, что ограничения нет
    («Все изменения сохранены»). Теперь это ошибка «Минимум должен быть числом», сохранение блокируется,
    введённый текст не стирается (+1 unit-тест на контракт `normalizeFormInput`).
  - P3: вкладка браузера редактора всегда называлась «Редактор формы» — теперь в заголовке название формы.
- Проверено и не подтвердилось (не менялось): лишнее нажатие «Назад» после ухода из редактора; отрисовка
  10 000 ответов разом (таблица уже выводит их порциями); устаревший список ответов (показывается и сразу
  обновляется в фоне). Работают как задумано: правка формы во время заполнения (409, ответы сохраняются),
  снятие с публикации во время заполнения, восстановление черновика после перезагрузки, конфликт двух вкладок,
  блокировка сохранения с ошибками.
- Не проверено (нет инструмента): двойное озвучивание уведомлений скринридером; поведение защиты от ухода
  в браузерах без Navigation API — все актуальные браузеры его поддерживают.

## 13. «Довести до 10 из 10»: девять независимых агентов, исправления, второй раунд ревью

- **Обещание «Node 20+» проверено по-настоящему.** Скачаны официальные Node 20.9.0 и 20.20.2 (проверка SHA-256).

  это описано в README). Итог проверен с чистой установки на Node 20.9, 20.20, 22 и 24: одна строка про ESLint 9
